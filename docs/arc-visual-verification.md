# Arc reference and visual acceptance contract

The user requires reference-based verification of both the plan and the implementation. Functional tests alone do not establish design fidelity. This contract updates the earlier minimal UI plan. Keep Browser's native macOS behavior and Liquid Glass; retain the useful structure and interaction hierarchy shown by Arc.

## Spaces acceptance

- Keep a minimal selector at the bottom of the vertical sidebar, outside the tab scroller. Per the user's explicit design correction, inactive Spaces are dots; only the selected Space shows its configured icon. Center the selector group in the sidebar, independent of trailing utility controls. Do not use a full-width glass capsule, boxed icon tiles, or a top dropdown as the primary switcher.
- Keep a separate discreet plus control, a distinct selected state, hover names, keyboard focus, and VoiceOver names and selection state. Many Spaces and narrow sidebars must remain usable; overflow must preserve centering, the selected icon, and access to every Space.
- Make the Space title/icon row optional through Settings → Appearance → Sidebar → Show Space title. Turning it off must remove the row and its layout space, not the bottom selector. Preserve existing folder design and behavior; the user clarified that the Space heading was mistaken for a folder.
- Preserve the established native sidebar material. Do not paint a theme-color wash, faux background, replacement material, or additional Essentials caption. Keep existing metadata and IDs backward-compatible; historical Arc tint is not permission to redesign Browser's sidebar.
- Edit Spaces in an anchored native popover, like folders, not a modal sheet. Reuse the folder editor's actual icon/emoji/colour component: the same 24-symbol eight-column palette, emoji field and system-picker hint, and icon colours. Do not create another approximate picker or decorative preview. Colours affect the icon only; inactive footer choices remain dots. Hold auto-hide sidebar chrome until the popover closes without revealing unrelated toolbar chrome.
- Support Control-number selection on macOS. Audit sidebar swipe behavior against the reference; do not substitute a mouse drag and claim trackpad verification.
- Preserve tab objects, page state, selected tabs, split focus, lazy inactive views, and profile identity while switching.
- Separate the scopes of Favorites/Essential tiles, Space Pinned Tabs/folders, and temporary tabs. Confirm the Favorites/profile relationship from official profile guidance before changing storage.
- Do not add a fake Share Space permalink or cloud sharing service. Record this as a deliberate local-only boundary.

## Command Bar acceptance

- Present an Arc-like floating palette, centered in the browser content area, instead of calling an ordinary address-field dropdown a Command Bar.
- Keep the command bar minimal: one native editor, small leading icons, left-aligned primary text and useful compact secondary URLs/details. Align the editor and rows on shared horizontal guides and centre each row's content vertically. The selected row itself must be a genuine Regular Liquid Glass pill, not a flat rectangular table highlight or a painted rounded fill. Its capsule follows selection and stays clear of the scroller; only that row shows one trailing Return symbol. Unselected rows have no selection surface or trailing affordance. Do not add visible action labels, Space/context columns, chips or explanatory helper copy. Preserve action and Space scope in accessibility labels/help. Keep the underlying page visible and use genuine Regular Liquid Glass with semantic colours, not simulated blur or copied Arc colours.
- Command-G toggles the command bar. When closed, it opens for the current live page with its full URL selected; when visible in any mode, it closes and restores focus without navigation. Opening it again selects the full current URL. Rapid queued toggles must not reopen a cancelled request. Unmodified prefilled URLs must retain exact-source intent, never become an unintended web search or activate another page. URL/search acceptance edits the exact source page rather than opening another tab. Command-T opens a blank palette for a new destination without eagerly creating a web view. Command-L retains native address editing. Escape and outside dismissal restore focus without navigation or a phantom tab. Preserve IME behavior and validate source identity before mutation.
- Preserve the checked local result/action engine. Accepted tab results select the exact existing tab, including when Peek is open. Rejected stale results must not change selection or dismiss valid work.
- Do not add inference on typing, misleading search-mode chips, or decorative controls without implemented actions.

## Verification gate for every UI section

1. Record the official behavior source and at least one usable visual reference where available. Distinguish text-only evidence, a reference image inspected, source review, XCTest, and actual GUI inspection.
2. Compare placement, hierarchy, density, selection, keyboard behavior, focus, and material treatment. List deliberate Browser adaptations and unresolved gaps.
3. Run Debug tests. Then use `just qa`, the installed `Browser-Debug.app`, a confirmed `--qa-profile`, and Built-in Retina Display for native screenshots and interaction checks. Do not use Release or a separate QA DerivedData copy. Leave Debug running.
4. Capture comparable states, not unrelated screens. Check narrow layout, multiple Spaces, long names, light/dark appearance, contrast, and keyboard-only interaction where relevant.
5. Keep a UI PR in draft until missing visual checks are explicit. A build, source rendering, DOM test, or synthetic event is not a passed native visual comparison.

## Current result

Reference inspection found two design gaps in the initial minimal implementation: a top Space menu instead of a bottom icon strip, and address suggestions instead of an Arc-like Command Bar. Their reference-aligned revisions are now implemented and tested. The independent audit also identified profile-shared Favorites and the Find-linked answer surface; these corrections are tracked separately.

A partial native pass on installed Debug source snapshot `dfebf2d` checked bottom placement, native icon/theme creation, six-Space overflow, Control-number selection and exact retained form state. Debug was moved with Window → Move to Built-in Retina Display and its fresh `--qa-profile` and native bounds were confirmed. The app was left running. A WindowServer-ID screenshot of the synthetic form and selected Work footer was saved and inspected; inactive capture is not proof of active glass treatment.

A separate installed Debug pass on QA merge `a9e3347` (Command parent `189accd`) confirmed the centered palette, active Regular glass, native address editing, no-phantom New Tab entry, outside-click swallowing and exact live form retention after a paced existing-tab round trip. It used injected OS keyboard/pointer events, not physical hardware. Built-in Retina Display, disposable launch arguments and explicit WindowServer screenshot ID were confirmed. An earlier unpaced macro produced an unintended dummy search; no successful retention claim is assigned to that attempt.

That Command pass found a real layout failure: with only three or five results at normal width, action/context labels and the final line were clipped. Correction `48d290f` now uses actual native row/clip/scroller geometry and passed its full Debug suite. An installed three-row recapture shows complete action/context labels and the complete final line. Five-row, narrow and appearance checks remain pending; passing earlier XCTest did not reveal the original native defect.

The user's minimal-selector correction is implemented in `03be524`: centered inactive dots, only the selected Space's configured icon, and a separate plus without an enclosing capsule or selected tile. Full Debug validation passed with 440 tests, two skips and no failures, including hosted keyboard-boundary regressions. Installed Debug QA merge `314efab` on Built-in Retina Display confirmed the three-Space layout, actual pointer selection, Control-number selection, and native Tab/Shift-Tab entry/exit through the address editor. Events were injected; physical keyboard/IME, VoiceOver and swipe are not claimed. This new check does not validate the new overflow popup or every narrow/appearance state. Debug was left running.

Revision `1c30ce1` removes the added sidebar color wash and visible Essentials caption, and adds the requested title-row preference. Full Debug validation passed with 446 tests, two skips and no failures. Installed QA merge `aaaf7ce` verified the actual Settings switch off/on/off against the main-window accessibility tree: the title row disappears and returns, while the bottom selector stays present. The final Debug window is left with the title row off. Folder code, native window material and existing tile glass remain unchanged. The rendered background regression compares three Space themes; it is not a complete appearance audit.

This is not full visual acceptance. Narrow resize requests snapped back; a source audit established no cause, so no speculative product workaround was added. Physical trackpad behavior, real webpage IME, VoiceOver, appearance/contrast variants and final integrated screenshots remain pending. Do not generalize either partial pass to Profiles, Archive, Ask or Favorites. Debug remains running; later metadata/swipe tests and source reviews do not retroactively validate those native states.
